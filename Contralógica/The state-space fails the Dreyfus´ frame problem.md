### 1. **The state space concept (Mari et al.)**

In Mari et al.’s framework, _state space_ is basically a structured set of all possible states an object could have with respect to a property (mass, length, impact factor, etc.). Measurement is construed as locating the object in one of those states, relative to a model.
This is a very **model-theoretic, representational device**: you define a property (say, mass), construct its state space (all possible values it can take), and then situate the object in one specific state (the measurand).

### 2. **The frame problem (Dreyfus’ critique)**

The _frame problem_ in AI/philosophy of mind:
- In short, it is the difficulty of representing what _changes_ and what _stays the same_ when an action is taken, without having to explicitly enumerate all the irrelevant details.
- Hubert Dreyfus used it to argue that **formal, symbolic models of intelligence fail**, because the real world is “open-ended” and resists being captured in a fixed set of states and rules. Human understanding is situated, contextual, and doesn’t operate by exhaustively specifying a “state space” of all possibilities.

### 3. **Does “state space” fail this test?**

Yes, potentially — for the following reasons:
- **Enumerative rigidity:** A state space presupposes that all relevant possibilities can be **predefined** in advance. Dreyfus’ frame problem highlights that in real-world contexts, relevance can shift unpredictably, and no finite state description can cover all contingencies.
- **Contextual overflow:** In measurement, background knowledge, environmental conditions, and instrument contexts matter. Mari et al. themselves stress that measurement involves _idealizations, approximations, and background knowledge_. This suggests that the state space abstraction leaves out exactly the kind of “practical know-how” Dreyfus emphasizes.
- **Dynamic, open-ended systems:** If the system evolves in unforeseen ways (new properties become relevant, definitions of measurands change, etc.), the predefined state space may no longer map reality. That’s structurally the same limitation Dreyfus pointed to in AI models.

### 4. **Possible reply from Mari et al.’s perspective**

However, Mari et al. don’t use “state space” in a strong metaphysical or exhaustive sense (as in classical AI). They use it as a **conceptual tool for structuring measurement tasks**, fully aware of “non-null definitional uncertainty” and the theory-ladenness of measurement. So one could argue:
- Their “state space” is _not meant to be complete_.
- It’s a **working model** that can be revised, refined, or extended — which partially sidesteps Dreyfus’ objection, though it doesn’t eliminate it.



**Ok, but if the concept of state-space is so deflated, is it still useful? Makes it sense to use that logic concept without the rigurosity of logic?**


### 1. What “state space” gives you when it’s rigorous

In **logic, physics, and engineering**, a state space is very precise:
- It’s a well-defined set of possible states of a system.
- Dynamics are modeled as transitions between states (via laws or functions).
- It allows for prediction, control, and formal reasoning.
This rigor is what makes the concept powerful in dynamical systems, control theory, and even in formal semantics.

### 2. What happens when Mari et al. use it in a “deflated” sense

In their paper, _state space_ is invoked much more loosely:
- They don’t enumerate all states; they only require the assumption that the object has a property that can be placed in some structured space.
- It becomes a **modeling convenience**: a way to say “the measurand corresponds to one element in a structured set of possible values.”
- They acknowledge uncertainty, idealization, and background dependence — so the “space” is really a _conceptual placeholder_.

### 3. Does this make it useless?

Not necessarily — but it changes its function:
- **It’s not a logical guarantee**: You don’t get the rigor of classical state-space reasoning.
- **It’s a heuristic scaffold**: It helps organize the measurement process by forcing you to think in terms of:
    - what property is being modeled,
    - what kinds of values it can take,
    - and how the measurement result is situated in that structure.
So the usefulness lies in **structuring measurement thinking**, not in providing airtight formal rigor.

### 4. Risk of “category mistake”

If one uses _state space_ while importing the **aura of mathematical precision** from dynamical systems, but without the actual rigor, then yes — it risks becoming **empty jargon**. That’s precisely the worry you’re raising.  
But if we recognize it openly as a **deflated, epistemic notion**, then it still makes sense: it tells us “measurement presupposes a space of possible outcomes, even if this space is theory-laden and revisable.”
